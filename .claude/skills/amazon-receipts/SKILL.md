# Amazon の領収書をまとめる

この文書のパスは、このリポジトリ (`~/local/src/github.com/tetsutan/amazon_receipt_downloader`) のルートからの相対パス。
ツールの説明は `README.md`、設計と Amazon の挙動の経緯は `docs/design.md`。

## 役割

- Claude: コマンドの実行、専用 Chrome と仕分け画面のサーバーの起動・停止、結果の要約
- 矢野氏: Amazon へのログイン (1Password のパスキー)、仕分け画面での会社 / 個人の選択、出力先の指定

## 守ること

- **期と、その期にかかる年の注文に触れてよいことを、最初に矢野氏に確かめる。** 期は終わりの年で書く (`2026` → 2025-11-01〜2026-10-31)。`orders <期>` は 2 つの暦年 (例: 2025 年と 2026 年) の注文一覧を開く。矢野氏が期を名指しして実行を頼んだなら、それが確認にあたる
- 取得したデータ (`data/`) には購入品・氏名・住所が入る。中身を会話に写すのは、ツールの出力 (注文番号・日付・金額・出品者) まで。PDF の本文や住所を読み上げない
- Amazon へのアクセスは `node receipts.mjs` のコマンドだけで行う。手で書いたスクリプトで PDF を取りにいかない (Node.js の通信やページ内の `fetch` で取ると、数十個で弾かれる。`docs/design.md` の「取得の方法について確かめたこと」)
- 終了コード 5 (弾かれた) が出たら、再実行しない。矢野氏に報告して止まる
- 長く動くコマンド (`sort` のサーバー、`fetch`) は Bash ツールの `run_in_background` で起動する

## 手順

### 1. 準備を確かめる

1 つずつ実行する。

```sh
node --version          # 22 以上
which pdftotext         # 無ければ矢野氏に `brew install poppler` を頼む
ls node_modules/playwright-core   # 無ければ npm install
```

### 2. 専用 Chrome を起動する

```sh
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:9222/json/version
```

- `200` なら起動済み。次へ
- それ以外なら `node receipts.mjs login` を実行する。Chrome の窓が開くので、矢野氏に「開いた Chrome の窓で amazon.co.jp にログインしてください (1Password のパスキーが使えます)」と頼み、済んだと言われるまで待つ。ログイン状態はプロファイルに残るので、2 回目以降は起動だけで済むことが多い
- `login` が「専用の Chrome が起動中で、『PDF をダウンロードする』の設定を書けない」で止まったら、矢野氏に専用の Chrome (Amazon にログインしている窓) を閉じてもらってから、もう一度 `login` を実行する

ログインできているかは、次の `orders` が終了コード 3 を返さないことで分かる。

### 3. 注文一覧を取得する

```sh
node receipts.mjs orders <期>
```

1〜3 分かかる。2 つの暦年の件数が表示される。失敗したら下の「終了コード」を見る。

### 4. 仕分け画面を起動し、矢野氏に仕分けてもらう

仕分け画面のサーバーを背景で起動する (`run_in_background: true`)。

```sh
node receipts.mjs sort <期>
```

ポート 8787 が使用中で起動できないときは、`pgrep -f "receipts.mjs sort"` で前回のサーバーを探し、`ps -o pid,command -p <PID>` で確かめてから止める。

起動したら、矢野氏に次を伝える。

- ふだんのブラウザで `http://127.0.0.1:8787/` を開く
- キー: `h` / `c` 会社、`l` / `p` 個人、`u` 未分類に戻す、`j` / `k` 次 / 前。「未分類だけ表示」で残りだけを出せる
- 合計 ￥0 の注文は一覧のいちばん下にある。ポイントやギフト券で全額払った会社の注文が混じりうるので、これも仕分ける
- 前に仕分けた注文 (前の期と重なる注文を含む) は、その結果が残っている
- 終わったら知らせてほしい

完了と言われたら、`node receipts.mjs status <期>` の 1 行目で「未分類 0 件」を確かめる。0 でなければ、残りの件数を伝えて仕分けを続けてもらう。仕分けが済んだらサーバーを止める (背景のタスクを止めるか、`pgrep -f "receipts.mjs sort"` で見つけて `kill`)。

### 5. 書類を取得する

```sh
node receipts.mjs fetch <期>
```

背景で起動する。会社の注文 1 件あたり 10〜20 秒かかる (50 件で 10〜15 分)。取得済みの注文は飛ばすので、途中で止まっても同じコマンドで続きから取れる。

### 6. 状況を確かめて矢野氏に伝える

```sh
node receipts.mjs status <期>
```

終了コード 1 は、未取得の注文が残っていること。5 からやり直す。表示を次の形で要約して伝える。

- 会社の注文の件数と、「すべて適格請求書」の件数
- 「適格請求書が無い」「両方ある」の注文 (日付・注文番号・金額・出品者)。適格請求書が無い分は、出品者に請求するかを矢野氏が決める (Amazon の「請求書のリクエスト」)
- 「返金の書類がある」の注文。`refund/` を見て、返金済みの商品の明細書を手で除く必要がある
- 「判定できない明細書がある」の注文。PDF を開いて確かめてもらう
- 状態が配達済みでない注文 (`[...]` で表示される)。後から書類が増えうるので、後日 `fetch <期> --refetch <注文番号>` で取り直す

### 7. 出力する

出力先を矢野氏に聞いてから実行する。

```sh
node receipts.mjs export <期> <出力先>
```

`<出力先>/<期間>/` (例 `2025-11-01_2026-10-31/`) を作り直す。このツールが作っていない同じ名前のフォルダがあると、消さずに止まる。

## 終了コード

| コード | 意味 | 対処 |
|---|---|---|
| 0 | 成功 | |
| 1 | そのほかの失敗。`status` では未取得の注文が残っている | メッセージを読む |
| 2 | 引数や前提の不足 (期の書式、未分類が残っている、一覧が無いなど) | メッセージのとおりに直す |
| 3 | ログイン画面に移った | 矢野氏に専用 Chrome の窓でログインしてもらい、同じコマンドをやり直す |
| 4 | 前回弾かれてから 3 時間たっていない | 待つ。急ぐかは矢野氏が決める (`--force`) |
| 5 | Amazon にエラーページを返された (弾かれた) | 再実行せず、矢野氏に報告する |

## 片付け

- 仕分け画面のサーバーは、仕分けが済んだら止める
- 専用 Chrome は閉じてもよい (ログインは残る)。閉じるかは矢野氏に任せる
