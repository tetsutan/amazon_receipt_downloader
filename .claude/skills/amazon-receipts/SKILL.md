# Amazon の領収書をまとめる

この文書のパスは、このリポジトリ (`~/local/src/github.com/tetsutan/amazon_receipt_downloader`) のルートからの相対パス。
ツールの説明は `README.md`、設計と Amazon の挙動の経緯は `docs/design.md` (前半は試作の時点の記録。食い違ったらこのスキルと `README.md` が正)。

## 役割

- Claude: コマンドの実行、専用 Chrome と仕分け画面のサーバーの起動・停止、結果の要約
- 矢野氏: Amazon へのログイン (1Password のパスキー)、仕分け画面での会社 / 個人の選択

## 守ること

- **期を数字で確かめてから始める。** 期は終わりの年で書く (`2026` → 2025-11-01〜2026-10-31)。引数か依頼に 4 桁の年があれば、それを期とする。「今期」「前期」「今年」のように言われたときは、期の番号と日付の範囲を示して確かめる。決算期は 11 月始まりなので、11〜12 月に「今期」と言われたときは、終わったばかりの期 (今年の年) を指していることが多い (2026-11 に矢野氏は「今期で言うと 2025/11/1〜2026/10/31」と述べた)
- `orders <期>` は 2 つの暦年 (例: 2025 年と 2026 年) の注文一覧を開く。期を確かめたことが、その 2 年の注文に触れてよいことの確認にあたる
- **`data/`、`out/`、専用プロファイル (`~/Library/Application Support/amazon-receipts/`) の下のファイルを Read / cat / grep で開かない。** 購入品・氏名・住所が入っている。会話に写すのは、ツールの出力 (注文番号・日付・金額・出品者) まで。中を見ないと原因が分からない失敗は、メッセージをそのまま矢野氏に伝えて止まる
- Amazon と専用 Chrome には `node receipts.mjs` のコマンドだけで触る。手で書いたスクリプトで PDF を取りにいかない (Node.js の通信やページ内の `fetch` で取ると、数十個で弾かれる。`docs/design.md` の「取得の方法について確かめたこと」)。ポート 9222 にブラウザ操作のツールや `curl` で接続しない
- 終了コード 5 (弾かれた) が出たら、再実行しない。矢野氏に報告して止まる
- `fetch` が終了コード 1 で止まったときは、再実行は 1 回まで。メッセージが「ダウンロードが終わらなかった」「『領収書等』を開けなかった」なら、弾かれた可能性があるので、再実行せずに矢野氏に報告する
- 長く動くコマンドは、`orders` は `timeout: 600000` を付けて実行し、`sort` と `fetch` は Bash ツールの `run_in_background: true` で起動する。背景のコマンドが終わったことは、完了の通知とその終了コードで知る

## 手順

### 1. 準備を確かめる

1 つずつ実行する。

```sh
node --version          # 22 以上
which pdftotext         # 無ければ矢野氏に `brew install poppler` を頼む
ls node_modules/playwright-core   # 無ければ npm install
```

### 2. 専用 Chrome を起動する

```sh
node receipts.mjs login
```

毎回実行する。Chrome を起動し (起動済みなら、専用プロファイルの Chrome であることと「PDF をダウンロードする」の設定を確かめ)、最後に amazon.co.jp のページのヘッダーでログイン済みかを確かめる。

- 「amazon.co.jp にログイン済み」と出たら、次へ
- 終了コード 3 (「ログインしていない」) で止まったら、矢野氏に「開いた Chrome の窓で amazon.co.jp にログインしてください (1Password のパスキーが使えます)」と頼み、済んだと言われたら `login` をもう一度実行する。ログイン状態はプロファイルに残るので、2 回目以降はログインが要らないことが多い
- 「ログインしているかを確かめられなかった」で止まったら、メッセージを矢野氏に伝え、ログイン済みかを聞く
- 「『PDF をダウンロードする』の設定を書けない」で止まったら、矢野氏に専用の Chrome (Amazon にログインしている窓) を閉じてもらってから、もう一度 `login` を実行する
- 「専用プロファイルの Chrome と確かめられない」で止まったら、ポート 9222 を別の Chrome が使っている。矢野氏に伝えて止まる

### 3. 注文一覧を取得する

矢野氏に「これから Amazon の注文一覧を取得します。終わるまで、専用 Chrome の窓と、ツールが開いたタブを閉じないでください」と伝えてから、`timeout: 600000` を付けて実行する。

```sh
node receipts.mjs orders <期>
```

1 ページに 4〜6 秒かかる (年 300 件なら 2 年分で 5 分前後)。2 つの暦年の件数が表示される。途中で止まっても前回の一覧は残るので、原因を直して同じコマンドでやり直す。

### 4. 仕分け画面を起動し、矢野氏に仕分けてもらう

仕分け画面のサーバーを背景で起動する (`run_in_background: true`)。

```sh
node receipts.mjs sort <期>
```

背景のタスクの出力に `仕分け画面: http://127.0.0.1:8787/` が出たら起動している。「ポート 8787 が使用中」で止まったら、`pgrep -fl "receipts.mjs sort"` で前回のサーバーを探し、`node receipts.mjs sort` の行の PID を `kill` してから起動し直す。

起動したら、矢野氏に次を伝える。

- ふだんのブラウザで `http://127.0.0.1:8787/` を開く (`localhost` では開けない)
- キー: `h` / `c` 会社、`l` / `p` 個人、`u` 未分類に戻す、`j` / `k` 次 / 前。「未分類だけ表示」で残りだけを出せる
- 合計 ￥0 の注文は一覧のいちばん下にある。ポイントやギフト券で全額払った会社の注文が混じりうるので、これも仕分ける
- 1 つの注文に会社と個人の物が入っていたら、どちらかに寄せる
- 前に仕分けた注文 (前の期と重なる注文を含む) は、その結果が残っている
- 終わったら知らせてほしい

完了と言われたら、`node receipts.mjs status <期>` の 1 行目で「未分類 0 件」を確かめる。この時点では書類を取っていないので、`status` は終了コード 1 (未取得がある) を返すのが正常。1 行目の未分類の件数だけを見る。0 でなければ、残りの件数を伝えて仕分けを続けてもらう。

仕分けが済んだらサーバーを止める (背景のタスクを止めるか、上の `pgrep` で見つけて `kill`)。

### 5. 書類を取得する

矢野氏に「これから会社の注文の書類を取得します。終わるまで、専用 Chrome の窓と、ツールが開いたタブを閉じないでください。そのブラウザで別のダウンロードもしないでください」と伝えてから、背景で起動する。

```sh
node receipts.mjs fetch <期>
```

会社の注文 1 件あたり 10〜20 秒かかる (50 件で 10〜15 分)。取得済みの注文は飛ばすので、上の「守ること」の範囲で、同じコマンドで続きから取れる。

`fetch` は、期の終わりより前に取った注文一覧のままだと止まる (終了コード 2)。そのときは 3 からやり直す。

### 6. 状況を確かめて矢野氏に伝える

```sh
node receipts.mjs status <期>
```

終了コード 1 は、未取得の注文が残っていること。5 からやり直す。表示を次の形で要約して伝える。

- 会社の注文の件数と、「すべて適格請求書」の件数
- 「適格請求書が無い」「両方ある」の注文 (日付・注文番号・金額・出品者)。適格請求書が無い分は、出品者に請求するかを矢野氏が決める (Amazon の「領収書等」にある「請求書のリクエスト」)
- 「返金の書類がある」の注文。`refund/` に置かれる。返金済みの商品の明細書は本体側の PDF に残るので、矢野氏が手で除く。「返金明細書」のリンクには、返品送料の適格請求書が入っていることもある
- 「判定できない明細書がある」の注文。矢野氏に PDF を開いて確かめてもらう
- 「PDF のリンクが無く、注文概要を印刷した」の注文。適格請求書の代わりにならないことがある
- 「配達が済んでいないかもしれない」の注文。後から書類が増えうるので、後日 `node receipts.mjs fetch <期> --refetch <注文番号>` で取り直す

### 7. 出力する

出力先はこのリポジトリの `out/` に固定してある (2026-11 の矢野氏の判断)。出力先は聞かずに実行する。

```sh
node receipts.mjs export <期>
```

`out/<期間>/` (例 `out/2025-11-01_2026-10-31/`) を作り直す。

- 「このツールが作ったフォルダではない」「このツールが置いたファイルではない」で止まったら、フォルダやファイルを消さない。どうするかを矢野氏に聞く
- 終わったら、置いた場所、置いた PDF の個数、`refund/` の個数、最後に出る「注意」の行を矢野氏に伝える

## 終了コード

| コード | 意味 | 対処 |
|---|---|---|
| 0 | 成功 | |
| 1 | そのほかの失敗。`status` では未取得の注文が残っている | メッセージを読む。`fetch` は「守ること」のとおり |
| 2 | 引数や前提の不足 (期の書式、未分類が残っている、一覧が古い、ポート使用中、出力先に他のファイルがあるなど) | メッセージのとおりに直す。ファイルを消して解決しない |
| 3 | ログイン画面に移った (`login` ではログインしていない) | 矢野氏に専用 Chrome の窓でログインしてもらい、同じコマンドをやり直す |
| 4 | 前回弾かれてから 3 時間たっていない | 待つ。急ぐかは矢野氏が決める (`--force`) |
| 5 | Amazon にエラーページを返された (弾かれた) | 再実行せず、矢野氏に報告する |

## 片付け

- 仕分け画面のサーバーは、仕分けが済んだら止める
- 全部終わったら、専用 Chrome を閉じるよう矢野氏に勧める。開いている間は、同じ Mac のほかのプログラムがポート 9222 からログイン済みの Amazon を操作できるため。ログインはプロファイルに残る
