# Amazon 領収書ダウンローダー 設計メモ

2026-11-16 に利用者と決めたことと、2023 年・2024 年の実データで確かめたことをまとめる。
本番のツールはこのメモに沿って作る。サンプル実装は `sample/` にある。

## 目的

利用者 (日本在住の個人) は、自分の amazon.co.jp の個人アカウントで、会社の物と個人の物の両方を買っている。
年に 1 回、会社の購入分の書類 (主に適格請求書) を税理士に渡す。ツールは次の 2 つを行う。

1. 指定した年の注文を一覧にし、利用者が会社 / 個人に仕分ける画面を出す
2. 会社に分けた注文の書類 PDF を取得し、税理士に渡すフォルダに置く

利用者の会社はインボイス登録をしている。税理士に渡すのは適格請求書。

## 環境

- macOS、Node.js (asdf で管理、v26)、Google Chrome 157
- ライブラリ: `playwright-core` (Chrome の操作)、`cheerio` (保存した HTML の読み取り)。PDF の文字の読み取りに `pdftotext` (Homebrew)

## 処理の流れ

1. ログイン
   - ツール専用の Chrome プロファイル `~/Library/Application Support/amazon-receipts/chrome-profile/` を使う
   - Chrome を `--user-data-dir=<上記> --remote-debugging-port=9222` で起動する (通常の Google Chrome を `open -na` で起動。Playwright からは起動しない)
   - 利用者が手でログインする。パスキーは 1Password に保存されている。1Password の拡張機能がデスクトップ版と連携するには、ふだんの Chrome にある `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.1password.1password.json` を、専用プロファイルの `NativeMessagingHosts/` にコピーする必要があった
   - Chrome を再起動してもログインは残った
2. 注文一覧の取得
   - `https://www.amazon.co.jp/your-orders/orders?timeFilter=year-<年>` を開き、`ul.a-pagination li.a-last a` を辿って全ページを保存する
   - 旧 URL (`/gp/your-account/order-history?...&orderFilter=year-<年>`) は絞り込みが無視され、最新の注文が表示された。URL の文字列で年を確かめるのは無意味で、表示された注文の日付をページ内で数えて確かめる
   - 日付の欄のラベルは「注文日」のほかに「サブスクリプション課金日」がある
   - 注文カードは `.order-card.js-order-card`。商品は `/dp/<ASIN>` へのリンクで集める (1 商品の注文と複数商品の注文で HTML の形が違う)。アプリストアの注文は `yo_fallback` を含むリンクに名前と画像が付く
   - 保存先: `tmp/<年>/raw/page-NN.html`、取り出した結果は `tmp/<年>/orders.json`
3. 仕分け
   - `sample/sorter-server.mjs` (127.0.0.1 で待ち受ける) と `sample/sorter.html`
   - 1 注文 1 枠で、商品の画像と名前をすべて横に並べる。キー: `h` / `c` が会社、`l` / `p` が個人、`u` が未分類、`j` / `k` で移動
   - 合計 ￥0 の注文と、キャンセル済み (合計が無い) の注文は出さない
   - 結果は `tmp/<年>/classification.json`
4. 書類の取得 (会社の注文だけ)
   - 注文カードの「領収書等」リンク (`/your-orders/invoice/popover?orderId=...`) を開いて HTML を保存する
   - その中のリンク: 「印刷可能な注文概要」(Web ページ) / 「明細書／適格請求書」(PDF、複数あると「明細書／適格請求書 1」「… 2」) / 「返金明細書」(PDF、複数あると番号付き) / 「請求書のリクエスト」(問い合わせページ)
   - PDF のリンク先 `/documents/download/<ID>/invoice.pdf` の `<ID>` は、「領収書等」を開くたびに変わる。リンクは「何番目か」で指す
   - PDF の取り方: 「領収書等」のページを開き、リンクをクリックする。専用プロファイルは Chrome の設定「PDF をダウンロードする」(`plugins.always_open_pdf_externally: true`) にしてあり、ダウンロード先は DevTools Protocol の `Browser.setDownloadBehavior` で作業用フォルダに向ける
   - 保存前に先頭が `%PDF-` であることを確かめる。違ったら止める
5. 出力 (未実装)

## 取得の方法について確かめたこと

| 方法 | 結果 |
|---|---|
| Playwright の `context.request` (Node.js 側の通信) で PDF を取る | 1.5 秒間隔で約 60 個、5〜8 秒間隔で 25 個取った後、PDF の代わりに Amazon のエラーページ (2153 バイトの HTML、HTTP 200) が返るようになった |
| 開いたページの中で `fetch` で取る | 上の状態が続いている間は 1 個目から同じエラーページ |
| リンクをクリックして開く / ダウンロードする | 上の状態が続いている間でも取れた。続けて 66 個 (5〜8 秒間隔) 取っても弾かれなかった |

エラーページは 1 時間 48 分後もまだ返っていた。いつ解けるかは測っていない。

## 書類の中身について確かめたこと

- 1 つの PDF に、出品者ごとの明細書が何枚も入っていることがある。1 枚の明細書が 2 ページに続くこともある (続きのページは同じ請求書番号)。`sample/statements.mjs` が全ページを読んで明細書に分ける
- 表題は「適格請求書」「支払い明細書」「返金明細書」「適格返還請求書」がある。リンクの文字は、適格請求書でも支払い明細書でも同じ「明細書／適格請求書」
- 2023 年 9 月以前 (インボイス制度の前) は、ほぼ「支払い明細書」。例外として、Amazon Services International (Kindle Unlimited) の 2023-09-29 の書類は表題が「適格請求書」で登録番号が `00003` (登録国外事業者)
- 10 月以降も、海外などの出品者の分は「支払い明細書」(本文に「この書類は適格請求書ではありません」)
- 2024 年の会社の注文 57 件: 明細書がすべて適格請求書 42 件 / 両方ある 11 件 / 適格請求書が 1 つも無い 4 件
- 返品のある注文の例: 「返金明細書 1」のリンクの中身が、返品送料 ￥500 の「適格請求書」だった。「返金明細書 2」が書籍の返金の「適格返還請求書」(−￥3,520)
- `pdftotext` で日本語を取り出せない PDF がある (Amazon Services International の 2024-10-29 の書類)。登録番号 `T2700150006138` は読めた
- 注文一覧の合計と、明細書の合計が一致しない注文がある (明細書のほうが大きいものもある)。理由は確かめていない
- 2023 年のデジタル注文で、「領収書等」に PDF のリンクが 1 つも無い注文があった (2024 年の会社の注文には無かった)

## 決めたこと

- C: 書類を取るのは、会社に分けた注文だけ
- D: 取るのは「明細書／適格請求書」のリンクの PDF
- E: 適格請求書が無い会社の注文も、支払い明細書をそのまま保存する
- F: リンクの文字が「返金明細書」で始まる PDF は `<出力先>/<年>/refund/` に置く。それ以外は `<出力先>/<年>/` に置く。返金済みの商品の明細書が `<出力先>/<年>/` 側の PDF に残ることは承知の上で、利用者が `refund/` を見て手で対処する
- G: 「領収書等」に PDF のリンクが 1 つも無い会社の注文は、「印刷可能な注文概要」を印刷 → PDF にして保存する
- H: 税理士用のフォルダには PDF だけを置き、一覧 (CSV) は置かない
- ファイル名: `<注文日>_<注文番号>_<番号>.pdf` (例 `2024-04-17_249-0768893-9870230_1.pdf`)
- 今の `index.js` (puppeteer 製、2020 年頃) は捨てて置き換える
- テスト中は、今年 (2026 年) のデータに触れない。本番では利用者が年を指定する

## Fable のレビューの後に決めたこと (2026-11-17)

- J: `refund/` に置くかは、PDF の中身ではなくリンクの文字で決める (返品送料の適格請求書が `refund/` に入ることは承知の上)
- K: 期は 11/1〜10/31 (決算期)。終わりの年で呼ぶ (`2026` → 2025-11-01〜2026-10-31)。注文日で絞る
- L: 1 つの注文に会社と個人の物が入っていても、どちらかに寄せる
- M: 合計 ￥0 の注文は隠さず、一覧のいちばん下にまとめて表示する (ポイントやギフト券で全額払った注文がある)
- 出力先のフォルダ名は期間 (`2025-11-01_2026-10-31/`)

## 本番の実装

`receipts.mjs` と `src/` (コマンドの一覧は `README.md`)。2026-11-17 に期 `2024` で通して試した。

- サンプルの 2023 年・2024 年のデータを `data/` に移し、会社の注文 3 件だけを `fetch` で取り直した (返金明細書 1 / 2 のある注文、1 つの PDF に明細書 4 枚の注文を含む)
- G の印刷 → PDF は、表示中の Chrome で DevTools Protocol の `Page.printToPDF` が動くことを、2023-05-04 の注文 1 件で確かめた。期 `2024` には該当する注文が無く、`fetch` の中では通っていない
- 弾かれたときの検出 (クリックの後にダウンロードにならずページに移る) は、弾かれた状態を作れず試していない
